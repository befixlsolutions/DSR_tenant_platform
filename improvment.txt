1) Bugs & Access Control Issues (High severity)
A) Role-gating is broken (security + product trust)

Employee can see Manager/Admin navigation items in the left sidebar:

Team Reports, Department Reports, Approvals, Exports.

Employee can open team-scope pages via URL (example in recording: /reporting?scope=team while role badge shows Employee).

This is not only a UI bug—if backend also returns data, it becomes a serious RBAC/ABAC leak risk.

Fix expectation

UI must hide these pages.

Server must block these routes and API calls for unauthorized roles.

B) Conflicting “Overdue” logic (data correctness)

On /reporting/inbox you show:

Banner: “6h 9m remaining”

But also a badge: “Overdue”

These can’t both be true. This breaks trust quickly.

Fix expectation

Overdue only after cutoff; otherwise show Due today or Due in X.

C) KPI inconsistency (dashboard trust)

On /home:

Goal Progress: 0/0

But also: “3 on track”

This is a logic mismatch or placeholder merge bug.

D) “Washed-out” table area looks like a UI bug

On /reporting?scope=team, the table/filter area appears faded/ghosted without clear reason.
This can be:

a disabled state without explanation

loading without skeleton

access denied but not handled

Fix expectation

If loading → skeleton loaders

If denied → clear “You don’t have access” screen

If empty → clear empty state with CTA

2) Usability Issues (Medium severity)
A) DSR “Quick Start” and “Same as Yesterday” lacks affordance

In DSR create screen:

“Same as Yesterday” looks like plain text (not an obvious action)

Needs a button style + preview/confirm

B) Blockers UX is too weak for a core object

“Add Blocker” is plain text; should be a proper button

Should open a structured modal (severity, owner, ETA, impact, escalation, linked goal/report)

C) No sticky action bar for Save/Submit

Users can scroll and lose track of submission controls. Enterprise apps fix this with a sticky bottom bar.

D) Adding bullet items is slower than necessary

You currently use input + Add button.
Better enterprise UX:

Enter-to-add

inline edit

reorder

quick remove

3) Role-Based UI: What should differ (your main issue)

Right now most roles look identical. In an enterprise app, each role should have:

different sidebar items

different dashboard widgets

different tables and drilldowns

different actions/buttons

Minimum role differentiation

Employee: “Do my work + submit reports”

Manager: “Review + unblock + coach”

Dept Admin: “Department execution + bottlenecks”

Org Admin/Owner: “Governance + configuration + adoption”

HR: “Appraisal readiness + fairness (aggregate)”

Auditor: “Logs + evidence packs (read-only)”
